# CLAUDE.md

## Project

Flee (Fast Lightweight Expression Evaluator): .NET expression parser/evaluator that compiles strings (e.g. `sqrt(a^2 + b^2)`) to IL via `DynamicMethod`. C# port of the original VB.NET project. Active branch: `v2-refactoring`.

## Build / Test

Multi-targets `net10.0;net9.0;net8.0;net7.0;net6.0;net5.0;netstandard2.1;netstandard2.0`. `<Nullable>enable</Nullable>` — keep warning-clean.

```bash
dotnet build Flee.sln
dotnet build Flee/Flee.csproj -f net10.0
dotnet test  Flee.Tests/Flee.Tests.csproj
dotnet test --filter "FullyQualifiedName~Flee.Tests.CalcEngineTests.CalcEngineTestFixture.Test_Basic"
```

NuGet pack is automatic (`GeneratePackageOnBuild=true`).

## Architecture

Pipeline: **parse → expression-element tree → emit IL → invoke**.

- `Flee/Parsing/` — hand-rolled `StackParser`/`RecursiveDescentParser` consuming `Expression.grammar` (source of truth). `FleeExpressionAnalyzer` walks the parse tree and emits `ExpressionElement` nodes.
- `Flee/ExpressionElements/` — typed AST. `Base/` (Unary/Binary/Member), operator subtypes, `Literals/` (split by numeric width), `MemberElements/` (Identifier, FunctionCall, Indexer, etc.), `Root.cs`. Each element has `Validate()` and `Emit(FleeILGenerator, IServiceProvider)`.
- `Flee/InternalTypes/` — `Expression<T>` (parses + emits into a `DynamicMethod`), `FleeILGenerator` (supports two-pass emit for long branches — see `Expression<T>.Compile` / `NeedsSecondPass()`), `ImplicitConversions`, `BranchManager`.
- `Flee/PublicTypes/` — `ExpressionContext` (compile via `CompileDynamic` / `CompileGeneric<T>`; cloned per expression unless `NoClone`), `VariableCollection`, `ExpressionImports`, `ExpressionOptions`. Hooks: `ResolveVariableType/Value`, `ResolveFunction`, `InvokeFunction`. `[ExpressionOwnerMemberAccess]` gates owner members.
- `Flee/CalcEngine/` — `CalculationEngine` (DAG of named expressions, `Recalculate(name)` propagates in topological order) and lighter `SimpleCalcEngine`. Uses a "temporary head" trick to allow forward references (see `FixTemporaryHead`).
- `Flee/Resources/` — `.resx` accessed via `FleeResourceManager` / `ResourceKeys.cs`.

### Generated parser files — DO NOT EDIT

`ExpressionAnalyzer.cs`, `ExpressionConstants.cs`, `ExpressionParser.cs`, `ExpressionTokenizer.cs` are generated by Grammatica. To change parser behavior: edit `Expression.grammar`, run `bash .claude/skills/regenerate-grammar/run.sh`, then re-apply the post-generation adjustments in `.claude/skills/regenerate-grammar/SKILL.md` (StackParser base, threading `ExpressionContext`, `CustomTokenPattern` for `ARGUMENT_SEPARATOR`/`REAL`).

## Tests

`Flee.Tests/` mirrors source layout. Data-driven inputs live in `TestScripts/` (the `.js` extension on some files is cosmetic — see `TestScripts/readme.txt`).

Add tests in the same change whenever you:
- Add a public class/method/operator/option — cover happy path + at least one edge case.
- Modify existing public behavior — add a regression test that would have failed before.
- Edit `Expression.grammar` — exercise new tokens/productions through `CompileDynamic`/`CompileGeneric<T>`, including longest-match interactions and string-literal behavior. Pattern: `Flee.Tests/ExpressionTests/CommentTests.cs`.
- Fix a bug — lock in the regression.

Pure refactors don't need new tests, but the suite must stay green. Don't mark a task done until tests are written and passing.

## Conventions

## Code Style

- **Max line length: 120 chars.** Break long string literals into concatenated pieces rather than letting them overflow. Try to make most of the 120 chars: avoid adding line breaks before reaching the line limit.
- **XML docs on every class, interface, enum, method, property, public member.** Always use `<param>`/`<returns>`/`<exception>`/`<remarks>` where applicable. Private members don't necessarily need docs.
- **C# `///` doc comments only.** Java-style `/** ... */` block comments must be rewritten as C# `///` triple-slash comments. The only exception is the four generated grammar files listed under "Generated parser files — DO NOT EDIT".
- `<summary>` must be a multi-line block:
  ```csharp
  /// <summary>
  /// Evaluates the expression.
  /// </summary>
  ```
  Never the single-line form `/// <summary>Evaluates the expression.</summary>`.
